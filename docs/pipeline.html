THE FITTED PIPELINE, STEP BY STEP

DATADOC has two moments: fit learns rules from training data, and transform reuses those frozen rules on other data.

1. The mental model

raw train data
      |
      v
profile -> plan -> fit
                    |
                    v
             pipeline.json
                    |
       +------------+------------+
       |                         |
       v                         v
 validation/test data      production inference data
       |                         |
       +---------- transform ----+
                         |
                         v
                    model features

The important rule is that medians, category vocabularies, clipping bounds, and scaling values are learned from the training rows only. Validation and test rows are never used to calculate those values.

2. CLI walkthrough

Start by inspecting a dataset. Profiling never modifies the file:

datadoc profile data.csv --target churn --output profile.json

Review the intended operations:

datadoc plan data.csv --target churn --output plan.json

Fit an artifact on the training split:

datadoc fit train.csv \
  --target churn \
  --task classification \
  --output artifacts/churn-pipeline.json

Apply the same state to validation or test data:

datadoc transform validation.csv \
  --pipeline artifacts/churn-pipeline.json \
  --output validation-features.parquet

Use the optional ML dependency when you want a baseline comparison:

pip install "datadoc-cli[ml]"
datadoc evaluate train.csv --target churn --task classification

3. Python walkthrough

import polars as pl
from datadoc import DataDocPipeline, PipelineConfig

train = pl.read_csv("train.csv")
validation = pl.read_csv("validation.csv")

config = PipelineConfig(
    target="churn",
    task="classification",
    scaling="standard",
)

pipeline = DataDocPipeline(config).fit(train)
features = pipeline.transform(validation)
pipeline.save("artifacts/churn-pipeline.json")

# Later, on another machine or process:
loaded = DataDocPipeline.load("artifacts/churn-pipeline.json")
same_features = loaded.transform(validation)

4. What is inside pipeline.json?

The artifact is ordinary JSON so contributors can inspect it in a code review:

  • config: target, task, scaling, identifier, and safety settings.
  • input_schema: the columns and types expected at transform time.
  • output_schema: the stable feature columns created by fitting.
  • state.numeric: training medians, missingness flags, and optional bounds.
  • state.categorical: one-hot categories or frequency dictionaries learned from training.
  • state.scaling: frozen centers and spreads.
  • profile and plan: findings and explanations behind the artifact.

5. Safety rules

Targets are protected. A declared target is never imputed, encoded, scaled, or dropped as a feature.

Identifiers are suggestions. Numeric shape alone cannot make a column an ID. Dropping requires an explicit policy.

Unknown categories are stable. New categories do not change the feature schema at inference.

AI is optional. The core does not require an API key, and AI-generated Python is never executed.

Schema changes fail clearly. Missing required columns and incompatible types produce actionable errors.

6. Evaluation and model performance

Cleaning does not guarantee a better score. DATADOC compares a minimal baseline and a candidate pipeline using cross-validation on the development rows, then evaluates the selected choice on a final holdout.

Classification reports balanced accuracy. Regression reports negative RMSE internally so candidate selection remains a “higher is better” comparison. Time and group columns can be configured for ordered or group-aware splits.

Retained text or identifier columns remain visible in prepared output but are excluded from the estimator matrix with a warning. Any remaining numeric missing values are filled with medians learned from the current training fold.

report = DataDocPipeline(
    PipelineConfig(target="churn", task="classification")
).evaluate(train_df, target="churn")

print(report.to_dict())

Use an untouched external test set for the final production decision. Treat the evaluation report as evidence, not as a universal promise.

OPEN-SOURCE CONTRIBUTOR NOTE

New transformations must learn state in fit(), reuse it in transform(), serialize it to JSON, and include leakage and artifact round-trip tests.
