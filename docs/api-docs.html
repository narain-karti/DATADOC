API DOCUMENTATION & TECHNICAL REFERENCE

Complete reference manual for the DATADOC CLI, Python Engine API, core plugins, and column role detection system.

1. CLI Commands

DATADOC provides a rich Command Line Interface built with Typer and Rich.

datadoc profile <file.csv> [--target col]

Analyzes the dataset and determines column roles (Identifier, Target, Numeric, Categorical) without applying transformations.

datadoc plan <file.csv> [--ai]

Generates a natural-language explainable plan for how the dataset will be transformed. Use --ai for LLM-assisted explanations.

datadoc fit <train.csv> [--output pipeline.json]

Learns statistics (medians, IQR boundaries, vocabularies) from the training data and serializes the state to a JSON artifact.

datadoc transform <test.csv> --pipeline pipeline.json

Deterministically applies a previously fitted pipeline artifact to unseen validation or inference data.

datadoc evaluate <train.csv> --task classification

Benchmarks the pipeline's effectiveness by training a baseline Scikit-Learn model (Random Forest / XGBoost).

datadoc run <file.csv>

A convenience command that automatically runs profile, plan, and fit in sequence for rapid prototyping.

2. Python DataDocPipeline API

The primary SDK class for interacting with DATADOC inside Python code:

class DataDocPipeline(config: PipelineConfig)

Methods:

  • fit(df: pl.DataFrame) -> self: Calculates all statistics and learns transformation rules from the provided training DataFrame.
  • transform(df: pl.DataFrame) -> pl.DataFrame: Applies the learned rules to the provided DataFrame, ensuring zero data leakage.
  • save(filepath: str): Serializes the fitted pipeline to a JSON artifact.
  • load(filepath: str) -> DataDocPipeline: Deserializes a pipeline from a JSON artifact.

3. Core Plugins Specifications

DATADOC runs 5 deterministic plugins sequenced by strict priority:

10: MissingValuePlugin PRIORITY 10

Behavior: Detects null values. Imputes continuous numeric features with column Median and categorical/string features with column Mode.

Dependencies: None

20: OutlierPlugin PRIORITY 20

Behavior: Identifies outliers on numerical features using Interquartile Range (1.5x IQR). Clips values outside $[Q1 - 1.5 \times IQR, Q3 + 1.5 \times IQR]$. Excludes binary (0/1) indicators.

Dependencies: MissingValuePlugin

30: DatetimePlugin PRIORITY 30

Behavior: Auto-parses datetime strings. Extracts temporal features (year, month, day, dayofweek, and hour if non-midnight times exist). Automatically drops the original datetime string and any zero-variance date features.

Dependencies: MissingValuePlugin

40: CategoricalEncoderPlugin PRIORITY 40

Behavior: Detects low-cardinality string columns and applies One-Hot Encoding (with drop_first=True). Auto-identifies and drops high-cardinality identifier columns.

Dependencies: MissingValuePlugin

45: ScalingPlugin PRIORITY 45

Behavior: Identifies continuous numerical features with large scale disparities (standard deviation ratio > 10). Applies Z-Score Normalization $(x - \mu)/\sigma$. Excludes binary 0/1 columns and constant features.

Dependencies: OutlierPlugin, CategoricalEncoderPlugin

4. Column Role Detection System

Before any plugins run, DATADOC's engine executes _detect_column_roles() to classify every column into one of four roles:

Roles:
1. "id"      -> Monotonically increasing unique integer series (Dropped automatically)
2. "name"    -> Unique string identifiers / UUIDs / high-cardinality names (Dropped automatically)
3. "constant"-> Zero-variance single-value columns (Dropped automatically at pipeline end)
4. "feature" -> Predictive numerical, categorical, or datetime features (Passed to plugins)
