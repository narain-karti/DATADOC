API DOCUMENTATION & TECHNICAL REFERENCE

Complete reference manual for the DATADOC CLI, Python Engine API, core plugins, and column role detection system.

1. CLI Commands

DATADOC provides a rich Command Line Interface built with Typer and Rich.

datadoc profile <file.csv> [--target col]

Profiles schema, nulls, cardinality, duplicates, findings, and confidence-scored roles without applying transformations.

datadoc plan <file.csv> [--target col]

Generates an explainable deterministic plan without modifying the dataset. AI is an optional advisory layer and is never required.

datadoc fit <train.csv> [--output pipeline.json]

Learns statistics (medians, IQR boundaries, vocabularies) from the training data and serializes the state to a JSON artifact.

datadoc transform <test.csv> --pipeline pipeline.json

Deterministically applies a previously fitted pipeline artifact to unseen validation or inference data.

datadoc evaluate <train.csv> --task classification

Compares a candidate against a minimal scikit-learn baseline using leakage-aware validation and a holdout. Install datadoc-cli[ml]; use --time-column or --group-column when required.

datadoc run <file.csv>

A convenience command that persists profile, plan, fitted artifact, transformed Parquet output, and a lineage manifest. It is a starting point, not a substitute for an explicit production holdout.

2. Python DataDocPipeline API

The primary SDK class for interacting with DATADOC inside Python code:

class DataDocPipeline(config: PipelineConfig)

Methods:

  • fit(df: pl.DataFrame) -> self: Calculates all statistics and learns transformation rules from the provided training DataFrame.
  • transform(df: pl.DataFrame) -> pl.DataFrame: Applies the learned rules to the provided DataFrame, ensuring zero data leakage.
  • save(filepath: str): Serializes the fitted pipeline to a JSON artifact.
  • load(filepath: str) -> DataDocPipeline: Deserializes a pipeline from a JSON artifact.

3. Core Plugins Specifications

The fitted pipeline contains five deterministic transformation concepts. The legacy plugin classes remain available for compatibility; production state is learned and serialized by DataDocPipeline.

10: MissingValuePlugin PRIORITY 10

Behavior: Fits numeric medians and categorical missing-value rules on training data. All-null columns become explicit findings.

Dependencies: None

20: OutlierPlugin PRIORITY 20

Behavior: Offers opt-in IQR clipping using bounds learned on training data. It excludes binary, target, identifier, and datetime-derived fields.

Dependencies: MissingValuePlugin

30: DatetimePlugin PRIORITY 30

Behavior: Parses date-like fields only when confidence passes the configured threshold, extracts stable calendar features, and reports parse warnings.

Dependencies: MissingValuePlugin

40: CategoricalEncoderPlugin PRIORITY 40

Behavior: Fits one-hot vocabularies for categorical features and handles unseen categories safely. High-cardinality fields are reported and are not silently dropped.

Dependencies: MissingValuePlugin

45: ScalingPlugin PRIORITY 45

Behavior: Applies configured standard or robust scaling to eligible numeric features, fit on training data only. Binary and protected fields are excluded.

Dependencies: OutlierPlugin, CategoricalEncoderPlugin

4. Column Role Detection System

The profiler classifies columns with confidence and rationale. It does not silently drop identifiers unless the user enables that policy.

Roles:
target              -> Explicit user-declared label (never transformed)
feature_numeric     -> Numeric feature with train-fitted statistics
feature_categorical -> String feature encoded from training vocabulary
feature_datetime    -> Parsed calendar features
identifier          -> Suspected ID; retained unless explicitly dropped
constant            -> Zero-variance or all-null feature

5. Optional AI advisory layer

AI is not part of the deterministic core. When enabled, it may receive opt-in minimized metadata and return a constrained, schema-validated plan. Generated code is never executed automatically.
