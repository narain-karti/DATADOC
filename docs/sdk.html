DATADOC PYTHON SDK GUIDE

Integrate DATADOC's high-performance, leakage-safe dataset engineering engine directly into your backend ML pipelines.

⚠️ LEGACY API DEPRECATED

The old doc.engineer() API has been fully deprecated due to data leakage concerns. Use the new DataDocPipeline architecture below.

1. Installation

DATADOC is available directly from PyPI. Install it in your environment or notebook cell:

pip install "datadoc-cli[ml]"

2. Quickstart (Fit & Transform)

DATADOC is a stateful pipeline. You must fit it on your training data, save the artifact, and then transform unseen validation data:

import polars as pl
from datadoc import DataDocPipeline, PipelineConfig

# 1. Load data
train_df = pl.read_csv("train.csv")
test_df = pl.read_csv("test.csv")

# 2. Configure & Fit the pipeline on TRAINING data ONLY
config = PipelineConfig(target="churn", scaling="standard")
pipeline = DataDocPipeline(config)
pipeline.fit(train_df)

# 3. Save the learned artifact (medians, IQR bounds, vocabularies)
pipeline.save("pipeline_artifact.json")

# 4. Transform unseen data deterministically
X_test = pipeline.transform(test_df)

3. Configuring the Pipeline

You can fine-tune how the pipeline behaves via PipelineConfig:

config = PipelineConfig(
    target="price",
    drop_identifiers=True,
    scaling="robust",
    clip_outliers=False
)

4. Why Split Fit/Transform? (Leakage-Safety)

If you impute missing values with the median of your entire dataset, your model is cheating because it learned statistics from the test set. DATADOC prevents this by strictly learning statistics during .fit() and applying those exact frozen statistics during .transform().

5. Evaluating the Pipeline

DATADOC includes optional model benchmarking through DataDocPipeline.evaluate() or the datadoc evaluate command:

metrics = pipeline.evaluate(train_df, target="churn")
print(metrics)
